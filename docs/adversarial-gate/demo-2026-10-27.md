# 对抗式验收全流程走查留档（PRD-171/T5）

> trend issue #859。验收标准：选 1 个 skill 走通；故意失败用例被拦；无密钥。
> 对象：虚构新 skill 样例 `adversarial-demo-skill`（测试夹具，不入 `skills/` 正式
> 目录），完整走 T2 独立 verifier（scripts/adversarial_verify.py 机检）+ T3 发布
> 门禁（scripts/adversarial_gate.py）。规范：docs/plans/2026-10-25-adversarial-
> acceptance.md（T1）。
> 本文所有数据为构造夹具数据；夹具脚本由测试构造并真实执行，verifier 的观察
> （退出码、输出）来自真实运行，非编造字符串。全文不含真实主机名 / IP / 账号 /
> 密钥（`tests/test_adversarial_t5.py::TestNoSecrets` 机检 + 阳性对照）。
> 机检复现：`python3 -m unittest tests.test_adversarial_t5 -v`。

以下命令均在测试构造的夹具仓库根执行，`<夹具根>` 为临时目录占位。

## 1. 阶段①：用例入库 + 无 findings 即拒

用例机检通过（冻结文件只读）：

```
$ python3 scripts/adversarial_verify.py --root <夹具根> cases adversarial-demo-skill
[cases] adversarial-demo-skill：PASS            # exit 0
```

故意失败场景 ①：published 且无 findings.json → 发布门禁拒（exit 1）：

```
$ python3 scripts/adversarial_gate.py --root <夹具根>
!! adversarial-demo-skill    published    缺 findings.json：未过门
FAIL：1 条违规
  - skill `adversarial-demo-skill` 已三处登记（published）但缺 findings.json：
    未过门（缺 findings 即拒，T1 §5 门禁规则）      # exit 1
```

## 2. 阶段②：独立 verifier 真实执行——误报被驳回

verifier 会话（`verifier-session-t5`，≠ 作者会话 `author-session-t5`）真实执行用例：

```
$ python3 tools/demo_digest.py --sum          # 红线反例（空输入）
exit 2；stderr: 缺输入：用法 demo_digest.py --sum <数字...>   → 红线未被推翻

$ python3 tools/demo_digest.py --sum 2 3 4    # 示例正例（误报现场）
exit 0；stdout: sum=7
```

POS01 主张「输出含 `sum=9`」与观察 `sum=7` 矛盾——**一条误报被 verifier 驳回**，
verdict = rejected，`disproved_by` 落最小复现。三态记录机检通过
（`[check] … PASS（4 条记录校验）`，exit 0），但门禁拦截（故意失败场景 ②）：

```
$ python3 scripts/adversarial_verify.py --root <夹具根> gate adversarial-demo-skill
[gate] adversarial-demo-skill：FAIL（core 2/3 confirmed，豁免 0，阻塞 1）
  - AC-adversarial-demo-skill-POS01：rejected 为终态，无豁免通道（修复回 skill 跟踪）
  · AC-…-NEG01：extended 用例 verdict=needs_validation（不阻塞）   # exit 1

$ python3 scripts/adversarial_gate.py --root <夹具根>
FAIL：1 条违规
  - skill `adversarial-demo-skill` 已三处登记（published）但对抗验收未过门
    （非 confirmed 不可 published）：…rejected 为终态，无豁免通道…  # exit 1
```

## 3. 阶段③：修复回 skill → 重验新开 record → 过门

作者修复脚本缺陷后，verifier 重跑（`sum=9`，exit 0），**重验新开 record
（`AV-…-05`），旧 rejected record（`AV-…-01`）保留不改写**（追加式历史）：

```
$ python3 scripts/adversarial_verify.py --root <夹具根> check --all
[check] adversarial-demo-skill：PASS（5 条记录校验）              # exit 0

$ python3 scripts/adversarial_verify.py --root <夹具根> gate adversarial-demo-skill
[gate] adversarial-demo-skill：PASS（core 3/3 confirmed，豁免 0，阻塞 0）  # exit 0

$ python3 scripts/adversarial_gate.py --root <夹具根>
OK adversarial-demo-skill    published    gate PASS（core 3/3 confirmed，豁免 0）
PASS：基线外 published skill 均过对抗验收门                      # exit 0
```

## 5. 反向对照（故意失败用例被拦的其余形态）

| 构造场景 | 机检结果 |
|---|---|
| verifier == author（自签） | `check` FAIL：「作者会话不可自签，独立性机检 FAIL」（T1 §6.1） |
| safety 用例（RED01）needs_validation + 豁免 | `gate` FAIL：「safety 用例 verdict=… 且不可豁免」（T1 §5 禁令） |
| rejected 挂 exempt_ref | `check` FAIL：「exempt_ref 仅 needs_validation 可填」（无豁免通道） |
| exempt_ref 未在台账登记 | `check` FAIL：「未在豁免台账登记」 |
| core needs_validation + 有效豁免（EX-20261027-01，对象为该 skill） | `gate` PASS：「豁免 1」（误杀保护放行且留痕） |
| 未三处登记（draft） | 不视为 published，不要求记录（exit 0） |

## 6. 验收标准逐条结论（trend #859）

| 标准 | 结论 | 证据 |
|---|---|---|
| 选 1 个 skill 走通 | ✅ | 虚构 skill `adversarial-demo-skill` 完整走 cases → check → gate 三阶段（§1–§4），终态 core 3/3 confirmed、发布面 exit 0 |
| 故意失败用例被拦 | ✅ | §1 缺 findings 即拒（exit 1）；§2 误报 rejected 后无豁免通道（exit 1）；§5 五类反向对照全部按预期拦截 |
| 至少 1 条误报被 verifier 驳回 | ✅ | POS01 主张 sum=9 vs 真实观察 sum=7 → rejected，`disproved_by` 落最小复现（§2、§4 record 01） |
| 机读 findings 齐全 | ✅ | §4 JSON 三态齐备、追加式历史完整；留档与走查终态逐字一致，机检复检通过 |
| 无密钥 | ✅ | 本文与夹具全为占位符/构造数据；`TestNoSecrets` 扫描 0 命中（含阳性对照） |

## 7. 边界与不影响面

- 夹具只存在于测试临时目录与本文留档，不入 `skills/` 正式目录、不入基线
  （`TestRepoArchive.test_fictional_skill_never_landed` 断言）；
- 真实仓库门禁不受破坏：`adversarial_gate.py` 全量 PASS、`cases --all` PASS
  （`TestRepoArchive.test_real_repo_gates_still_green`）；
- 不改 T1–T4 交付（scripts/adversarial_verify.py、scripts/adversarial_gate.py、
  既有用例清单）的任何行为。
