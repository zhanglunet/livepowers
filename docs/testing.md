# 测试

## 脚本与仓库结构

```bash
python -m unittest discover -s tests -v
```

| 文件 | 覆盖 |
|---|---|
| `tests/test_lp.py` | 盈亏平衡、F-V-S-R、中文路由、注册与退役（含 `--supersedes`）、写操作必须带测试、生成者不能自验、调用次数统计、能力复核、任务看板（非法迁移、缺理由、缺证据、自验、止损、接管不能直达生产、重开须重置、closed 终态）、结果台账（含指标方向、成本须基线）、资产四道门、作业契约、夜间产物清单、金丝雀、`--help`、钩子自动采集（S1 调用、S2 补记、显式记录优先、未 init 不写文件、坏输入不报错、可关闭）、置信度与复核、意图同义词表（别名归并证据与路由、规范化 task / pending、相似意图建议）、晨报 |
| `tests/test_surface.py` | 活软件展示面：校验拒绝可执行代码 / 本体外对象 / 写语句 / 内嵌数据 / 写操作能力 / 缺本体；record 只落元数据并写 S2 证据；promote 建任务与候选；对账一致与不一致；部署失败回滚与外部回执核验人；无生产回执拒绝注册、`pages list`、退役下线；模板可校验；参考宿主端到端（次抛 → 申请固化 → grow.sh → 命中固定页）与前端不执行展示面内容 |
| `tests/test_scan_and_switch.py` | 扫描（外键、命名推断、敏感字段跳过、状态抽样）、指纹与漂移；交换机的中转、策略拒绝、超长消息、收件、旁路、回放、审计、篡改检测 |
| `tests/test_repo.py` | 技能 frontmatter、路由表与 README 覆盖、技能互相引用、清单版本一致（含 package.json）、会话钩子在三种平台的输出、证据采集钩子的注册与端到端、示例脚本、可选敏感词黑名单 |
| `tests/test_npm.py` | npm 安装器：各目标目录、个人 / 项目安装、已存在时跳过与 `--force`、安装清单、AGENTS.md 合并与卸载清理、`--dry-run`、`list` / `path`、参数错误、`lp` 转发；`npm pack` 只含运行时文件（需要 node / npm，缺失时跳过） |

发布前可以设置黑名单，检查仓库里没有不该出现的名称：

```bash
LP_DENYLIST="名称1,名称2" python -m unittest tests.test_repo -v
```

## 技能（行为测试）

按 `skills/writing-livepowers-skills/SKILL.md`：

1. 为技能设计 2–3 个压力情境，例如"用户很急""模型已经答对了，直接注册吧""这次只是临时查一下"。
2. 在没有该技能的会话里运行，逐字记录 Agent 跳过的步骤和给出的借口。
3. 装上技能后再跑同样的情境，确认 Agent 现在会遵守。
4. 把新发现的借口补进技能的反模式表，再验证一遍。
