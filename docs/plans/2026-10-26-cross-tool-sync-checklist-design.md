> 借鉴：xingkongliang/skills-manager 的"同步检查"思路（协议未核实，只借鉴思路，不复用代码）
> 事实基线：本仓库 README 安装节、`docs/plans/2026-10-18-npx-install-t1-report.md`、

## 1. 定位与边界

- 本条管用户侧一件事：**装得到、装得对**——一份 skill 在 Claude / Cursor / Codex / Pi
  四个工具里，装了没、版本对不对、旧版残留清了没。
- 与 PRD-130（多 harness 发布矩阵）划界：PRD-130 是发布侧（包发到哪些渠道）；
  本条是消费侧（用户机器上的安装状态与发布版是否一致）。两者只在 §9 的
  "发布清单"一个接口上相接。
- 与 PRD-199（agentskills 规范对齐）划界：PRD-199 管 skill 文件写成什么样才算标准
  （frontmatter 规范）；本条只读安装状态做比对，不校验、不改写规范性。
  两条共用同一份"期望 skill 清单"数据源（§3）。
- 与 PRD-212（其他仓的同步清单）关系：清单设计共用、实现分仓。本文的状态枚举
  （§7）与检查项分层（§4）按可跨仓共用的口径写，路径表（§6）各仓自备。
- 非目标（继承 PRD）：**不做自动静默更新**。检查过程零写入；修复只输出建议，
  由用户手动执行（§8）。

## 2. 事实基线：安装通道与落点（均来自仓库一手记录）

| 通道 | 落点 | 来源 |
|---|---|---|
| skills CLI 全局 `--all -g` | `~/.agents/skills/<skill>`，再链接进各 agent 目录 | PRD-058/T1、T3 实测 |
| skills CLI 项目级 `-y` | `<project>/.agents/skills/<skill>` | PRD-058/T1、T3 实测 |
| npm 安装器（默认 `--target claude`） | `~/.claude/skills/<skill>` | README 安装节 |
| npm 安装器 `--project`（codex / cursor） | 项目内技能目录；cursor 另生成 `.cursor/rules/livepowers.mdc` 入口规则 | README 安装节 |
| Claude Code 插件 | `plugins/livepowers-*` 五个插件，`plugin.json` 带 `version` | 仓库 `plugin.json` |
| Codex 插件 / 手动 | `.codex-plugin/plugin.json`；或手动拷贝 `skills/*` 到 `~/.agents/skills/` | README 安装节 |
| Cursor 插件 | `.cursor-plugin/plugin.json` 与 hooks | README 安装节 |
| 网页端 zip | `scripts/package-skills.sh` 打包，逐个上传到客户端技能页 | README 安装节 |

由基线得出的三条设计前提：

1. **同一 skill 在一台机器上可以有多份**（多通道 × 多工具 × 多项目）。
   检查的基本单位不是 skill，而是"安装实例"（§3）。
2. **SKILL.md frontmatter 没有版本字段**（只有 `name` / `description` /
   `allowed-tools`，PRD-058/T3 抽样确认）。版本判定必须分锚级别（§4 的 V 组），
   不能假装读一个版本号就完事。
3. **skill 数量会变**（PRD-058 时 19 个，现 `skills.sh.json` 5 分组共 20 个）。
   检查项与输出形态不得写死数量，一律以期望清单为准。

## 3. 检查对象模型

- **期望侧（expected）**：当前发布版的 skill 清单 + 每 skill 的参考指纹
  （SKILL.md 内容哈希）+ 所属插件版本号。
  - 清单来源：仓库 `skills/` 目录与 `skills.sh.json` 分组，二者不一致时以
    `skills/` 目录为准并在报告中提示清单源不一致。
  - 获取优先级：本地仓库 checkout > 用户指定的参考目录 > skills.sh 索引页
    （见检查项 E-02：参考源不可达时版本类检查整体降级，不拿旧缓存冒充最新）。
- **实际侧（actual）**：安装实例 = {工具, 范围（全局 / 项目级）, 路径,
  发现方式（安装器记录 / 目录扫描 / 插件清单）}。
- **检查粒度**：skill × 安装实例。矩阵（§7）是实例结果的聚合视图。

## 4. 检查项总表

分五组：C 存在与完整、V 版本、R 残留、E 环境。每项给出判定口径与主要误判风险；
四工具各自的具体判定方式见 §5 矩阵。

### C 组：装了没 / 完整不完整

| 编号 | 检查什么 | 判定口径 | 主要误判风险 |
|---|---|---|---|
| C-01 | 工具技能根是否存在 | 根目录不存在 → 该工具记"未检出"（中性状态，不算异常） | 工具装了但从未用过技能功能、目录尚未创建 → 文案区分"未检出"与"未装 skill"，不报缺失 |
| C-02 | skill 装了没 | 期望清单中每个 skill：在该工具技能目录下有同名目录且含 `SKILL.md` | 同名目录存在但无 SKILL.md → 记"不完整"而非"已装" |
| C-03 | 清单完整性 | 已装数 vs 期望数；列出缺哪些、多哪些（多出的转 R-02 继续判定，不直接报异常） | 用户故意只装子集（交互选择、只启部分插件）→ 记"部分安装"，属正常态，不报警 |
| C-04 | 可识别性 | 已装 skill 的 SKILL.md frontmatter 中 `name` / `description` 可读（agent 靠它识别，PRD-058/T3 口径） | 文件被本地改坏 → 只报"不可识别"事实，不推导版本结论 |

### V 组：版本对不对

版本锚分三级，检查结果必须标注用了哪一级：

- **A 级**：插件 `plugin.json` 的 `version`，或安装器留下的安装记录——有真版本号。
- **B 级**：SKILL.md 内容指纹（哈希）与期望侧参考指纹比对——只能判"一致 / 不一致"。
- **C 级**：无锚（只有目录时间戳等弱信号）——不参与版本判定，只在详情中展示。

| 编号 | 检查什么 | 判定口径 | 主要误判风险 |
|---|---|---|---|
| V-01 | 版本锚读取 | 按 A → B → C 顺序取该实例可用的最高级别锚，锚级别随结果一起输出 | 插件装与目录装并存时锚不同级 → 按实例分别标注，不混算 |
| V-02 | 版本 / 指纹比对 | A 级：版本号低于发布版 → 漂移·旧；高于 → 漂移·新（本地超前，如自构建版）；相等 → 最新。B 级：指纹一致 → 最新（限 B 级口径）；不一致 → "内容不一致" | B 级不一致可能是旧版、也可能是用户本地改过 → 文案只写"内容不一致"，不武断判旧（处置建议分叉见 §8） |
| V-03 | 实例间一致性 | 同一 skill 的多个实例版本是否齐平；不齐平在汇总区单列"实例间漂移" | 项目级故意钉旧版 → 项目可在路径表声明 pinned（§6），声明后不报漂移 |

### R 组：旧版残留

| 编号 | 检查什么 | 判定口径 | 主要误判风险 |
|---|---|---|---|
| R-01 | 同名双份 | 同一工具内同一 skill 出现两份及以上（如插件装 + 目录拷贝、全局 + 项目级同工具生效）→ 标残留，并指出按该工具加载优先级哪份生效；优先级无法确定时写"生效份待确认" | 全局与项目级本就是两份设计内安装 → 只有"同工具同范围双份"或"生效份不确定"才标残留，跨范围双份只在详情列出 |
| R-02 | 已下架 skill 残留 | 本地有、期望清单没有的 skill：靠历史版本指纹库或安装记录确认是否本包旧 skill → 是则标"已下架残留" | 归属无法确认的只列"未知来源"，不建议删除（§8） |
| R-03 | 失效链接残留 | skills CLI 是"中央目录 + 链接进各 agent 目录"形态：中央已删、链接残留（悬空链接）→ 标"失效链接" | 目标暂不可达（网络盘、权限）→ 先判可达性，不可达记"无法确认"，不当残留 |
| R-04 | 旧入口残留 | 入口文件（如 `.cursor/rules/livepowers.mdc`、项目 AGENTS.md 入口段）与 skill 本体的新旧关系：入口有版本标记则比对；无标记只查存在性 | 入口是用户手动维护的 → 只报存在性事实，不报漂移 |

### E 组：环境与降级

| 编号 | 检查什么 | 判定口径 | 主要误判风险 |
|---|---|---|---|
| E-01 | 路径可达性 | 路径不存在 / 无读权限 → 该实例整体记"无法检查"并单列原因 | 这是**防误报总闸**："无法检查"绝不混进"未装" |
| E-02 | 参考源可达性 | 期望侧取不到（离线、无本地仓库）→ C 组照常跑，V 组整体记"跳过：无参考源" | 用过期缓存当参考源会把新版误报成漂移 → 禁止静默用缓存，确需用时在报告头注明参考源日期 |

检查项合计 **13 项**（C×4、V×3、R×4、E×2；其中 E 组为降级口径，不计异常数）。

## 6. 路径表可配置原则

PRD 风险节的第一条就是"各工具安装路径差异导致误判"，对策落在这一节：

- **路径不写死**：所有落点集中在一张路径表（数据文件）里，每条含
  {工具, 范围, 路径模板（支持 `~` 与环境变量展开）, 版本锚类型,
  同工具多落点的加载优先级, 来源（实测 / 文档 / 待校准）, 置信度}。
- **覆盖顺序**：命令行参数 > 用户配置（沿仓库惯例放
  `<LIVEPOWERS_HOME>/config.yaml`）> 路径表默认值。
- **项目级范围可控**：默认只查"当前项目 + 全局"；要查多个项目，用户在配置里
  给项目根列表，不做全盘扫描。
- **pinned 声明**：项目级实例可声明钉版，声明后 V-03 不报漂移（有意为之不算问题）。
- **误判可反馈**：每个异常结论都附判定依据（用了哪条路径、哪级锚、比对了什么），
  用户发现误判时能指着依据说"这条路径不对"，改路径表即可，不用改代码。

## 7. 同步状态表输出形态

### 7.1 主形态：skill × 工具矩阵

- 行 = skill，按 `skills.sh.json` 的 5 个分组（Core / Ontology / Delivery /
  Night / Tooling）排列；列 = Claude / Cursor / Codex / Pi 四工具。
- 单元格 = 该 skill 在该工具下的**聚合状态**（多实例时取优先级最高的状态，
  并标注实例数，如 `部分安装 ×2`）；实例明细在详情区展开。
- 矩阵上方是汇总区，遵循 PRD-046 简洁输出规范的三段式：结论一句话
  （如"20 个 skill：全同步 X / 漂移 Y / 残留 Z"）→ 关键信息 ≤5 条
  （最需处理的在前）→ 详情（完整矩阵 + 实例明细，折叠）。
- 人类可读输出收紧，机器可读输出（`--json`）字段由 T2 定，但**状态枚举语义
  以本文为准**，T2 / T3 不得自行增改；变更走本文档修订。

### 7.2 状态枚举（单元格级，按优先级从高到低取）

| 状态 | 含义 | 对应检查项 |
|---|---|---|
| `无法检查` | 路径不可达 / 无权限，附原因 | E-01 |
| `残留` | 有残留：同名双份 / 已下架 / 失效链接 / 旧入口 | R-01…R-04 |
| `版本漂移·旧` | A 级版本号低于发布版 | V-02 |
| `版本漂移·新` | A 级版本号高于发布版（本地超前） | V-02 |
| `内容不一致` | B 级指纹不一致（旧版或本地修改，不武断） | V-02 |
| `部分安装` | 工具内多实例状态不一，或清单只装了子集 | C-03、V-03 |
| `同名非本包` | 同名目录但指纹与历史版本均不符，疑似用户自建 | C-02、R-02 |
| `未装` | 该工具下无此 skill | C-02 |
| `已装最新` | 在该实例锚级别口径下与期望一致（详情注明 A / B 级） | V-02 |
| `未检出工具` | 工具技能根不存在（中性，不计异常） | C-01 |

示意（占位示例，仅示形态）：

```
同步检查：20 个 skill × 4 工具，参考源 本地仓库（发布版 x.y.z）
漂移 2 处、残留 1 处、无法检查 1 处，其余同步。

skill               Claude      Cursor      Codex       Pi
system1-first       已装最新(A)  已装最新(B)  版本漂移·旧  未装
explore-with-evidence 已装最新(B) 未装        已装最新(B)  无法检查(无权限)
...（完整矩阵在详情区）
```

## 8. 漂移与残留的"建议"口径（T3 的设计输入）

- **只检查、只建议**：建议以"问题 + 依据 + 建议命令"三段呈现；命令以用户
  手动复制执行为前提。检查过程本身零写入、零删除、零自动更新。
- **可直接抄的命令**：漂移·旧且归属明确时，给对应通道的更新命令
  （如 `npx skills add zhanglunet/livepowers -y` 或
  `npx livepowers install --force`，按该实例的来源通道选）。
- **先看 diff 再决定**：`内容不一致`（B 级）与`同名非本包`不给覆盖命令，
  只建议先对比内容——可能是用户本地改过，覆盖会毁掉本地修改。
- **删除类建议单独成段、排最后**：措辞统一为"确认无用后可删"，附删除前
  备份提示；`未知来源`的 skill 永不给删除建议。
- 每条建议标注来源检查项编号（如"依据 V-02"），保证可追溯、可反馈误判。

## 9. 与发布流水线的衔接点（T4 的设计输入）

- 本检查的期望侧需要一份机器可读的**发布清单**，由发布侧（PRD-130 流水线）
  在发版时产出或更新。T1 只定它必须包含的字段：
  {skill 名, 所属插件, 插件版本, SKILL.md 参考指纹, 发布日期, 历史版本指纹列表
  （供 R-02 归属判定）}。
- 新版发布后"提示用户跑一次同步检查"的触发在发布侧；本条只保证被提示后
  一条命令能跑完检查（命令形态 T2 定）。

## 11. 待评审决策点

   是否需要合并为一个状态（代价：丢失"可能被本地改过"的信息）。
