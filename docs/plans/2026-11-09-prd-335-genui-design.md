## 3. 组件树 schema 设计

### 3.1 节点结构（T2 预埋）

```json
{
  "type": "文本标签",
  "props": {"text": "…（占位）", "size": "标准"},
  "children": []
}
```

- 树形嵌套（children 递归），深度上限 6（防失控嵌套，超深整树拒绝）；
- 节点数上限 50（防爆炸）。

### 3.2 组件类型词表（封闭集，R2）

| type | 属性白名单 | 必填 |
|---|---|---|
| 文本标签 | text, size(标准/大/小) | text |
| 字段行 | label, value | label, value |
| 分组框 | title, children | title |
| 分隔线 | — | — |
| 提示条 | text, tone(提示/警告) | text |

- 词表五类覆盖配置页需求（标题/字段/分组/分隔/提示）——**刻意小**：表达力不够时走词表增补评审，不走模型自由发挥；
- 每类属性白名单如上，白名单外属性 → 丢弃+显形（R1）。

### 3.3 属性校验规则（T3 落地）

1. `props` 键 ∉ 白名单 → 丢弃该属性 + `dropped[]` 记录；
2. 必填属性被丢（如 text 超长被丢）→ 整节点拒绝（节点缺必需信息不可渲染）；
3. 枚举属性值 ∉ 枚举 → 回退默认值 + `dropped[]` 记录；
4. `dropped[]` 随渲染产物输出——丢弃显形给人工复核（不静默）。

## 4. 渲染器（T2/T3 落地）

- 单一渲染函数 `render(tree) → lines[]`（纯函数，输出纯文本行序列——skill 配置页场景无需真 GUI，终端/文本即可）；
- 流式：树可分批喂入（逐子树渲染，前缀不变）；
- **同库断言**（R3）：预览与最终调用同一 `render`——T4 断言渲染函数单一来源、零第二实现。
