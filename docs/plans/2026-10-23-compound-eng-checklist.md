# PRD-147/T1：官方级工程标准 checklist 草案（测试/文档/示例/安全）

## 1. 定位与分工：为什么已有 PRD-094 还要这套

PRD-094 已定稿 31 条收录 checklist（C-01–C-31，`docs/PRD-094-store-checklist.md`），回答的是"官方市场收不收"；本 checklist 回答的是"够不够格以 livepowers 的名义发布"——官方不考、但工程上必须过的部分：测试完备度、示例可复现、登记同步、写操作红线。两套并存、不合并，发布门禁按"先瘦身后工程"串联（选题门见 PRD-148，工程门即本文）。

借鉴说明：[EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin)（MIT，25,660★）的工程门不在一张平铺清单里，而是编码进强制流程（simplify → report-only review → compound）。本文借鉴两点：**条目尽量给"可用命令复核"的验收方式**（为 T2 编码进 CI 做准备）、**评审只报告不代改**（打分人不动手修，修复回各 skill 跟踪）。全部条目为按本仓库现状另写的自研表述，未复制上游文本；如后续需引用其清单原文，须保留其 MIT 版权声明。

现状基线（2026-10-23，main `a5d4e65`）：skills/ 共 **21 个**（契约测试 `EXPECTED_SKILL_COUNT = 21`）；插件对象 6 个（根插件 + core 5 skills / ontology 4 / delivery 7 / night 2 / tooling 3）；CI `test.yml` 跑 Python 3.9/3.11/3.13 三版本矩阵，含 `TestNoIdentifyingInfo`（LP_DENYLIST 可配）识别信息扫描；`tests/<skill-name>/test_examples.py` 与 skills 一一对应；`tests/triggers/<name>.jsonl` 触发用例；打分表模板在 `docs/prd-094-scorecard/`。PRD-094/T4 已补齐：allowed-tools 全量声明（#83）、插件 README 快速上手与配置项（#82）、icon 资产（#81）、`.cursor-plugin/marketplace.json`（#80）、homepage/repository（#79）——这批是本 checklist 的现存达标面。

## 2. 公共约定

| 约定项 | 口径 |
|---|---|
| 条目编号 | `E-<类><两位序号>`：T=测试、D=文档、X=示例、S=安全（如 E-T01）。与 PRD-094 的 C-01–C-31 不共用编号空间，映射关系只走第 4 节的单向引用表 |
| 打分 | 0 / 1 / 2：2=完全满足，1=部分满足（有但不全/不规范），0=缺失或违反。判定条件逐条写死，不打自由分 |
| 门禁级别 | **阻断** / **常规**。阻断：得 0 或 1 分即挡发布，不可豁免；常规：1/0 分可修复，或走第 5 节豁免登记（限期） |
| 适用范围 | skill / 插件 / 仓库三层（沿用 PRD-094 决策记录 Q4：三层分开算分、不折总分） |
| 证据强制 | 每条打分必须附证据（文件路径 + 字段/行号，或命令输出存档位置）；无证据视为未打分（沿用 PRD-094 口径） |
| N/A | 不适用标 N/A 并写明理由，不计入分母 |
| 版本标 | 本 checklist v0.1（2026-10-23 草案）；定稿后每次修订升小版本并在文末变更节记录 |
| 过门判定 | 阻断级条目全部得 2 分，且（常规级得 2 分数 ÷ 常规级适用条目数）≥ 90%。任一不满足 → 修复或豁免，否则不出发布 PR |

## 5. 过渡期豁免字段设计

PRD 风险节要求"允许过渡期豁免字段但须标注"。设计如下：

**登记位置**：集中台账 `docs/engineering-checklist/exemptions.md`（T1 只定字段，T2 落文件）；打分表复用 `docs/prd-094-scorecard/scorecard-template.md` 结构，证据登记表增加"豁免 ID"一列，二者以豁免 ID 关联。

**台账字段（逐条一行）**：

| 字段 | 说明 |
|---|---|
| 豁免 ID | `EX-<YYYYMMDD>-<两位序号>`，如 EX-20261025-01 |
| 对象 | 层级 + 名称（如 `skill: night-loop-planning`） |
| 条目 | E 编号（只允许常规级条目；阻断级条目填了即台账本身违规） |
| 分数 | 1 或 0 |
| 理由 | 一句话，写清"为什么现在修不了" |
| 影响与风险 | 一句话，写清"带病发布的后果由谁承担" |
| 补偿措施 | 可选；如"发布后在 README 标注限制" |
| 批准人 | 不得与该条目的实现者是同一人（呼应本仓"生成者 ≠ 采纳人"铁律） |
| 期限 | 版本号或日期，默认 1 个 minor 版本；到期自动失效 |
| 到期复审结果 | 字段预留：恢复打分 / 续期一次 / 升级为跟踪 issue |

**规则**：① 阻断级不可豁免；② 同一对象同时有效的豁免 ≤3 条；③ 同一条目不得连续豁免两次——第二次必须修复或立跟踪 issue；④ 豁免条目从达标率分母剔除（同 N/A 待遇），但在报告里标 `EXEMPT` 而非空白；⑤ 台账随打分报告走，T2 脚本读到 `EXEMPT` 条目时输出为"豁免"而非"失败"。
