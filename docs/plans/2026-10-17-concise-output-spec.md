# PRD-046/T1：livepowers 统一简洁输出规范 v0.1（草稿）

> 状态：草稿，待确认后进 T2（存量改造清单）
> 借鉴：JuliusBrussee/caveman（Apache-2.0，思路借鉴）

## 1. 总则

- 所有 skill 的**人类可读输出**遵循本规范；机器可读输出（`--json`）保持原样不动。
- 展示层只收紧，不删信息：被折叠的内容仍可展开/用开关恢复。
- 字数上限是硬约束：超限的输出必须截断并提示"已折叠 N 行"。

## 2. 三段式格式

```
一句话：做了什么 / 结果是什么（≤50 字）
要点列表，每条 ≤30 字，最多 5 条
折叠：完整日志/数据/证据，需要时展开
```

### 2.1 执行结果类（如 gen_harness、安装、部署）

- ：`成功：<产物> 已生成到 <路径>` 或 `失败：<一句话原因>`
- ：产物清单 / 耗时 / 下一步命令（可直接抄）
- ：完整 stdout/stderr

### 2.2 诊断类（如故障排查、审计）

- ：根因一句话（≤50 字）
- ：证据链 Top 5（每条：现象 → 依据）
- ：完整检查过程

### 2.3 错误类

- ：错在哪（≤50 字）
- ：先给可直接抄的修复命令，再给 1-2 条备选
- ：完整堆栈/错误上下文

### 2.4 查询类（如查状态、查列表）

- ：答案一句话
- ：表格只保留关键列（≤5 列），行数 >20 则只显示前 10 行 + "共 N 行，已折叠"
- ：完整结果

## 3. 禁止事项

- 禁止输出"正在处理…"这类无信息量的过程废话超过 1 行。
- 禁止把同一信息在结论和关键信息里重复说两遍。
- 禁止在里放需要滚动才能看到的内容。

## 4. 开关（T3 细化，T1 先定口径）

- `LIVEPOWERS_VERBOSE=1` 或配置文件 `verbose: true` → 恢复全量输出。
- 默认：简洁模式开启。
- 调试/排障场景文档中注明可临时关闭。
