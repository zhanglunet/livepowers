# skill 生成监督台设计草稿（PRD-446/T1）

## 1. 背景与问题

skill 包一旦上架就进插件市场，有问题的包上架后影响的是所有装它的
用户。生成式 skill 出炉时，人看不见 agent 是怎么拼出这个包的，要到
上架审批才发现问题。本设计让人在生成全程看得见 agent 是怎么拼出这个
包的：每步可见、批注得了、一点发回重做。

## 2. 目标

- 每个 skill 包都带生成过程 + 批注 + 发回反馈三件套落账。
- 问题包在生成时就被批注发回重做，不等上架审批。
- 上架队列只剩人点头过的包；未点头的 skill 包不上架审批。
- 批注与反馈全程留痕。
- skill 生成不碰上架审批权：监督台不管审批结论，只管生成过程。

## 3. 非目标

- 不管包成稿：包成稿评审是 PRD-423 评审流水线的事。
- 不验安检发现真假：安检发现验证是 PRD-377 插件安检发现验证台的事。
- 不管拍板那一刻：拍板时刻归 PRD-363 收件箱管。
- 不碰上架审批权：上架审批的通过与否仍由审批环节决定，监督台不代行。
- 本设计只管 agent 干活的全程——人看、agent 改。

## 4. 设计要点

### 4.1 监督台的三个构件

| 构件 | 说明 |
|---|---|
| 进度（Progress） | skill 包生成每一步的状态机：待开始 / 进行中 / 待复核 / 已点头 / 已发回。步骤粒度：模板选取 → 字段填充 → 校验 → 打包，每步可见。 |
| 批注（Annotation） | 人对某一步的意见，锚定到步骤与包内字段：含作者、时间、所指步骤、所指字段 / 文件、文本、状态（待处理 / 已采纳 / 已驳回）。 |
| 发回反馈（Feedback） | 一点把"换模板 / 补字段"发回 agent 的动作。反馈含目标步骤、改动诉求、期望模板或字段；发回即生成一条待办进生成循环，改完出新版回到监督台复核。 |

### 4.2 数据模型（概念级）

- **SupervisionSession**：一次 skill 生成任务对应一个监督会话；含任务引用、创建时间、当前状态。
- **StepRecord**：生成内某一步的记录；含步骤序号、步骤名、输入摘要、输出摘要、所涉字段 / 文件、状态、耗时。
- **PackageVersion**：每版 skill 包的记录；含版本号、包引用、生成步骤摘要、状态；版本链可回溯。
- **Annotation**：见 4.1；一条批注属于一个 StepRecord，可挂包内字段或文件。
- **FeedbackTicket**：一次发回；含来源批注、诉求文本、目标步骤、状态（待处理 / 处理中 / 已回炉 / 已关闭）、回炉后的新 StepRecord / PackageVersion 引用。
- **ApprovalGate**：关口裁决；含裁决人、裁决时间、结论（点头 / 发回）、备注。点头按包版本给出；只有点头的包版本才进上架审批。

### 4.3 接入点

- skill 生成任务启动时创建 SupervisionSession；每完成一步写 StepRecord，每出新版写 PackageVersion。
- 批注入口常驻监督台：人在任意步骤、任意包内字段上点"批注"，锚定步骤 + 字段 / 文件。
- 发回入口在每条批注与每个步骤上：一点即生成 FeedbackTicket，生成循环收到后按诉求换模板或补字段。
- 上架审批队列只接收 ApprovalGate 为"已点头"的包版本；未点头的 skill 包不上架审批。

### 4.4 监督回路时序

1. 生成 agent 干活，每步与每版实时进监督台，人同屏看生成过程。
2. 人在可疑步骤上批注（锚定字段 / 文件），一点发回"换模板 / 补字段"。
3. agent 按 FeedbackTicket 重做，出新版回到监督台复核。
4. 人复核新版：满意则关闭反馈；对当前包版本点头。
5. 点头后包版本进入上架审批；不点头则停在监督台，不外流。
6. 上架审批权不受影响：监督台不决定包能不能上架，只决定包能不能进审批队列。

### 4.5 与现有能力的关系

- 复用 skill 生成现有的模板与字段定义，不另起包结构。
- 复用上架审批队列的"点头才进"语义：监督台是上架审批的上游关口。
- 批注形态借鉴 plannotator"批注 → 裁决 → 一键发回 agent"（见第 7 节借鉴声明）。

## 5. 验收标准（T1 设计评审）

1. 本文档覆盖数据模型、接入点、关口规则三部分，无缺项。
2. 批注可锚定到步骤与包内字段 / 文件；发回可定位到目标步骤；回炉后可复核。
3. "未点头不上架审批"的关口规则写死为必选项，不是可选项。
4. skill 生成不碰上架审批权：监督台不含任何审批通过 / 驳回路径。
5. 批注与反馈全程留痕：每条批注、每次发回、每次裁决都有作者与时间。
6. 红线章节（第 6 节）与借鉴声明（第 7 节）完整在位。
7. 本文档为原创文字，不含实现代码；不改目标仓现有代码。
