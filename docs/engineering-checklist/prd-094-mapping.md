## 1. 映射原则

- **C 条目是收录视角（外部考官），E 条目是工程视角（自家门槛）**。重合条目以 C 的判定
  原文为依据下限，E 只收紧或补证据口径，不放松。
- 关系三档：**同判定**（同一件事，E 补验收命令或证据口径）、**延伸**（同一主题，E 收紧
  或扩大范围）、**新增**（官方标准不管、工程上必须；其中个别新增条目是对某 C 条目的
  延伸，差异说明里注明源头）。
- 未被 E 条目引用的 C 条目（结构/元数据类）**不在工程 checklist 重复打分**——它们是
  收录格式问题，发布门禁直接引用 PRD-094 打分结果（`docs/prd-094-scorecard/`），避免
  两表打架。
- 打分一次采集、两表分报：`scripts/eng_checklist.py` 的证据可直接复用为对应 C 条目的
  打分证据（同判定的 6 条尤其如此）。

## 4. 汇总口径

- 被 E 引用的 C 条目：**10 条**（C-18、C-20、C-23、C-24、C-25、C-27、C-28、C-29、
  C-30、C-31）；收录侧自管：**21 条**（结构 5 + 元数据 14 + validate/开源 2）。
  10 + 21 = 31，全量覆盖、零遗漏。
- 新增型 E 条目（E-T02、E-T04、E-D04、E-X04、E-S04）**不对应任何 C 条目**：官方标准
  不考，纯工程门槛；其中 E-T02 的判定思想源自 C-30 的「缺目录 = 测试缺失」延伸。
- 打分表复用：同判定条目（E-T01/E-T03/E-D01/E-D02/E-D03/E-S01/E-S02/E-S03 对应
  C-30/C-31/C-20/C-24/C-25/C-27/C-28/C-29）一次采集证据，两表各记一分；E 得分不
  反向决定 C 得分（收录打分仍以 `docs/PRD-094-store-checklist.md` 判定原文为准）。
- 本表变更走 checklist 版本标（v0.x）：E 条目增删或映射关系变化时，本文与
  `scripts/eng_checklist.py` 的 ITEMS、`tests/test_checklist_mapping.py` 三处同步改。
